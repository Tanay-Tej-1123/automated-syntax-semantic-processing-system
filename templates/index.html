Compiler Phases Architecture & Flow

Phase 1: Lexical Analysis

Scans source text character-by-character, strips comments, maps lexemes to defined Token Types, and reports illegal characters or unterminated strings.

Phase 2: Syntax Analysis

Uses Recursive Descent Parsing following MiniLang EBNF grammar to verify language structure and generate the Abstract Syntax Tree (AST).

Phase 3: Semantic Analysis

Maintains scoped Symbol Tables across global and nested blocks, enforcing declaration-before-use, type compatibility, and unique variable names.

Semantic Validation Rules Enforced

  • Declaration Before Use: Any identifier accessed in an expression or assignment must be previously declared in the current or an ancestor scope.
  • No Redeclaration in Same Scope: Identifiers cannot be declared multiple times within the same block scope. (Shadowing in inner nested blocks is allowed).
  • Strict Type Compatibility: Assignments require identical types, with safe widening of int into float permitted.
  • Expression Type Checking: Arithmetic operators (+, -, *, /, %) require numeric operands, with + overloaded for strings. Relational operators require numeric operands and yield bool. Logical operators require bool operands.
  • Control Flow Guards: Conditions in if and while statements must evaluate to bool.
  • Constant Division by Zero: Divisors with literal zero (0 or 0.0) are caught and reported at compile time.

Compiler Design Viva Q&A (Project Presentation Guide)

Q1. What is the objective of this project?

To design and implement an end-to-end automated compiler frontend for MiniLang that performs real Lexical, Syntax, and Semantic analysis, producing detailed diagnostic errors and symbol tables without mockups or hardcoded results.

Q2. What parser technique is used?

A Recursive Descent Parser (Top-Down LL(1) parsing technique). Each non-terminal in our EBNF grammar corresponds to a Python function. Precedence climbing is used to properly handle operator precedence.

Q3. How does the symbol table handle lexical scoping?

The symbol table uses a hierarchical tree structure with parent pointers. When entering a block { ... }, a child symbol table is pushed. Lookup checks the current scope first, then walks up to parent scopes. On exiting, the scope pops back to the parent.

Q4. What is the difference between Syntax and Semantic analysis?

Syntax analysis checks whether the tokens follow the grammatical structure of the language (e.g. balanced braces, semicolons, valid statement structure). Semantic analysis checks the meaning and consistency (e.g. whether variables are declared before use, types match, and operations are valid).
